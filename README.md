# Alpacabitollama

A standalone desktop application for running local LLMs via llama.cpp, packaged with a modern SvelteKit WebUI, system tray integration, automatic backend downloads, and an OpenAI-compatible API server.

## Overview

Alpacabitollama brings together:

- **llama.cpp inference engine** — Automatically downloads the correct GPU/CPU backend binaries from [ggml-org/llama.cpp releases](https://github.com/ggml-org/llama.cpp/releases).
- **Modern SvelteKit WebUI** — Chat interface, model management, and settings.
- **System tray integration** — Runs in the background; restore from tray.
- **OpenAI-compatible API** — Exposes `http://127.0.0.1:13434/v1` for IDE integrations and third-party tools.
- **Interactive API Explorer** — Built-in Swagger UI for exploring the REST API.
- **Bundled Documentation** — Docusaurus docs site with guides, API reference, and troubleshooting.
- **HuggingFace model service** — Curated model list + search any GGUF repo.
- **jCodeMunch code retrieval** — Structured code context from GitHub repos and local workspaces.
- **Web search** — DuckDuckGo search with result fetching.
- **User registration & authentication** — Local user accounts stored securely.

## Quick Start

### 1. Install desktop dependencies

```bash
cd desktop
npm install
```

### 2. Build the WebUI

```bash
cd ../webui
npm install
npm run build
```

The SvelteKit static adapter outputs to `../public`.

### 3. Copy assets into the desktop bundle

```bash
cd ../desktop
npm run copy-webui
```

This copies:
- `../public` → `desktop/public/` (webui static files)
- `../media` → `desktop/resources/` (icons)
- Any local `llama-server` binary + DLLs from a sibling `llama.cpp/build` (optional)

### 4. Run in development

```bash
npm start
```

### 5. Build installer / portable executable

```bash
# Windows installer
npm run build:installer

# Windows portable
npm run build:portable

# Both
npm run build
```

## Performance & Lazy-Start

The desktop app uses two techniques to eliminate blank screens and reduce RAM usage:

### Persistent Splash Screen

Instead of repeatedly reloading the window during startup (which caused black flashes), the app now loads a single `splash.html` and updates it via IPC messages. This provides smooth visual feedback while the backend downloads, the model loads, and the webui initializes.

- **`desktop/public/splash.html`** — Branded splash screen with spinner and progress bar
- **`desktop/splash-manager.js`** — Main-process module that sends IPC updates to the renderer

### Lazy-Start Server

By default the app now keeps `llama-server` offline until you explicitly click **Start Chatting**. This prevents the model from consuming RAM/VRAM while the app is idle. When you activate it, the server starts in the background and the webui loads automatically.

- **`desktop/lazy-start-manager.js`** — Settings, landing-page HTML generation, and on-demand boot flow
- **Setting:** `lazyStart.enabled` (stored in `electron-store`) — `true` by default for new installs

You can disable lazy-start to restore the previous auto-start behavior.

## Backend Auto-Download

If no local `llama-server` binary is bundled, Alpacabitollama automatically:

1. Detects your hardware (CUDA, ROCm/HIP, Vulkan, CPU AVX2/AVX512).
2. Queries the latest [llama.cpp release](https://github.com/ggml-org/llama.cpp/releases).
3. Downloads the correct backend archive (e.g. `win-cuda-12.4-x64`, `ubuntu-vulkan-x64`, `macos-arm64`).
4. Extracts it into `%APPDATA%/alpacabitollama/backends/<tag>/<backend>/`.
5. Verifies that all required DLLs are present (Windows).
6. Optionally downloads the CUDA runtime DLL package for Windows CUDA builds.

This means **end users do not need to compile llama.cpp** — the app is self-contained.

## OpenAI-Compatible API Server

When the server is running, an OpenAI-compatible endpoint is available:

```
Base URL: http://127.0.0.1:13434/v1
Chat:    POST /v1/chat/completions
Models:  GET  /v1/models
```

### API Explorer (Swagger UI)

Browse and test the API interactively via the built-in Swagger UI:

- **From the app** — Go to **Settings → Developer → Open API Explorer**
- **From the docs site** — Navigate to `/api-explorer` in the bundled documentation
- **Direct file** — Open `docs/static/api-explorer.html` in a browser

The OpenAPI spec lives at `docs/static/openapi.json` and covers all endpoints: chat completions, embeddings, model listing, and health checks.

### IDE Integration

Configure host/port in **Settings → API Server** inside the app, or via the tray menu:
- **Copy OpenAI Endpoint** — copies the base URL to your clipboard for use in IDEs (VS Code, Cursor, etc.)

## Feature Highlights

### Model Management
- Curated GGUF models (Qwen, Llama, Gemma, Mistral, Phi, SmolLM2, Bonsai).
- Search and download from any HuggingFace GGUF repository.
- Active model switching without restarting the app.
- Vision/multimodal support via `mmproj-*.gguf` projector files.

### jCodeMunch Code Retrieval
- Index GitHub repositories directly from web search results.
- Browse local workspace folders via folder picker.
- Search symbols (functions, classes, methods) with natural language.
- Retrieve exact source code with byte-accurate offsets.

### Web Search
- DuckDuckGo search integration.
- Fetch and extract page content for chat context.
- Automatic text extraction from HTML.

### User System
- Local user registration with SHA-256 password hashing.
- Login/logout and profile updates.
- Data stored in `%APPDATA%/alpacabitollama/` (Windows) or `~/.config/alpacabitollama/` (macOS/Linux).

## Troubleshooting

### WebUI not found
Build the webui first: `cd webui && npm install && npm run build`

### llama-server binary not found on first run
This is expected if you haven't bundled a local build. The app will auto-download the correct backend from GitHub releases when you first start the server.

### Missing VC++ Redistributable (Windows)
If llama-server crashes immediately with code `0xC000007B` or `0xC0000135`, install the [Microsoft VC++ Redistributable](https://aka.ms/vs/17/release/vc_redist.x64.exe). The installer can bundle this via `resources/vc_redist.x64.exe`.

### CUDA backend missing DLLs
The binary manager verifies `ggml-cuda.dll`, `ggml.dll`, `llama.dll`, etc. If any are missing after extraction, it will log a warning and the server may fall back to CPU inference. Ensure the CUDA runtime ZIP was also downloaded.

### Connection Issues with IDE Integration
See [AGENTIC_IDE_INTEGRATION.md](./AGENTIC_IDE_INTEGRATION.md#troubleshooting) for detailed troubleshooting of IDE integration issues.
